# 13. Pull Production and Kanban Implementation

## 13.1 Transitioning from Push to Pull

### Understanding Push vs. Pull Production

**Traditional Push Production:**
- Production schedules based on forecasts
- Each workstation produces according to schedule
- Work moves forward regardless of downstream demand
- Results in inventory buildup between operations
- Overproduction masked by inventory

**Pull Production Philosophy:**
- Production triggered by actual customer demand
- Nothing produced until needed by next process
- Visual signals control production authorization
- Inventory naturally limited by system design
- Problems immediately visible

### Preparing for the Transition

**Assessment Phase:**
1. **Current state analysis**
   - Map existing push system
   - Identify inventory levels
   - Document lead times
   - Measure system performance
   - Understand product families

2. **Readiness evaluation**
   - Process stability assessment
   - Quality capability review
   - Equipment reliability check
   - Workforce skill level
   - Management commitment

**Key Prerequisites:**
- Stable processes (minimal defects)
- Reliable equipment (high uptime)
- Quick changeovers (SMED implemented)
- Level scheduling capability
- Cross-trained operators
- Standardized work in place

### Transition Challenges

**Common Obstacles:**
1. **Cultural resistance**
   - "We've always done it this way"
   - Fear of not meeting customer demand
   - Concern about operator idle time
   - Measurement system conflicts

2. **Technical barriers**
   - Unreliable equipment
   - Long changeover times
   - Quality issues
   - Supplier capability

3. **System issues**
   - ERP system conflicts
   - Scheduling practices
   - Performance metrics
   - Layout constraints

**Overcoming Resistance:**
- Start with pilot area
- Demonstrate quick wins
- Educate before implementing
- Address concerns directly
- Show data and results
- Involve operators early

## 13.2 Designing the Pull System

### System Architecture

**Basic Pull System Elements:**

```
Customer → Finished Goods → Production → Raw Materials → Suppliers
              ↓                  ↓              ↓            ↓
          Withdrawal         Production    Withdrawal  Supplier
            Kanban            Kanban        Kanban      Kanban
```

### Product Family Analysis

**Grouping Products:**
1. **Similar processing requirements**
   - Same equipment
   - Similar operations
   - Comparable cycle times
   - Shared tooling

2. **Volume considerations**
   - High runners (frequent production)
   - Medium runners (periodic production)
   - Slow movers (occasional production)

3. **Routing similarities**
   - Common process sequences
   - Shared workstations
   - Similar material flows

**ABC Analysis Application:**
- **A items:** Make to stock, frequent replenishment
- **B items:** Make to stock, periodic review
- **C items:** Make to order or minimal inventory

### Pull System Levels

**Level 1: Simple Two-Bin System**
- Best for: Low-value items, simple products
- Mechanism: One bin producing, one bin consuming
- Signal: Empty bin triggers replenishment

**Level 2: Kanban Card System**
- Best for: Multiple products, moderate complexity
- Mechanism: Cards authorize production/movement
- Signal: Card return triggers next production

**Level 3: Electronic Kanban**
- Best for: Complex systems, many SKUs
- Mechanism: Electronic signals via software
- Signal: System-generated production orders

**Level 4: Advanced Pull (CONWIP)**
- Best for: Job shops, high variation
- Mechanism: Constant work-in-process limits
- Signal: Job completion releases new job

### Pacemaker Process Selection

**Identifying the Pacemaker:**
- Closest process to customer
- Point where production is scheduled
- Upstream processes are "pulled"
- Downstream processes often continuous flow

**Example in CNC Shop:**
```
Raw Material → Sawing → CNC Milling → CNC Turning → Assembly → Ship
                  ↑                       ↑ (Pacemaker)
              Pull System            Schedule Here
```

### Pull System Design Decisions

**Key Design Questions:**

1. **Where to place inventory?**
   - Between which processes?
   - How much at each location?
   - Physical storage location?

2. **What signals to use?**
   - Cards, containers, electronic?
   - Two-bin or multiple cards?
   - Visual or automated?

3. **How much inventory?**
   - Safety stock requirements
   - Replenishment lead time
   - Demand variability
   - Container size

4. **Replenishment frequency?**
   - How often to produce?
   - Batch sizes?
   - Changeover impact?

## 13.3 Supermarket Sizing and Location

### What is a Supermarket?

**Concept:**
- Controlled inventory storage location
- Organized by product type
- Visual inventory management
- Customer (downstream process) "shops" here
- Producer replenishes only what's consumed

**Difference from Traditional Warehouse:**
- Limited SKUs (product family focus)
- Smaller quantities
- Frequent replenishment
- Located at point of use
- Visual min/max levels
- Pull signals integrated

### Supermarket Location Strategy

**Location Principles:**
1. **Close to consuming process**
   - Minimize transportation
   - Enable frequent withdrawal
   - Easy visual control
   - Operator accessibility

2. **Efficient for replenishment**
   - Reasonable distance from producer
   - Easy kanban signal visibility
   - Material handling efficiency

3. **Physical constraints**
   - Available floor space
   - Existing layout
   - Safety considerations
   - Traffic patterns

**CNC Shop Examples:**

**Raw Material Supermarket:**
- Location: Between receiving and first operation
- Contents: Bar stock, plate, standard sizes
- Organization: By material type and size
- Replenishment: Vendor-managed inventory

**WIP Supermarket:**
- Location: Between CNC and secondary operations
- Contents: Machined parts awaiting next process
- Organization: By part number
- Replenishment: CNC cell produces to kanban

**Finished Goods Supermarket:**
- Location: Between assembly and shipping
- Contents: Completed products
- Organization: By customer or product line
- Replenishment: Final assembly to customer pull

### Supermarket Sizing Calculations

**Basic Formula:**
```
Supermarket Quantity = (Average Daily Demand × Replenishment Time)
                       + Safety Stock
```

**Detailed Calculation:**

**Step 1: Determine average demand**
```
Average Daily Demand = Annual Volume / Working Days
                     = 5,000 parts / 250 days
                     = 20 parts/day
```

**Step 2: Calculate replenishment time**
```
Replenishment Lead Time = Setup + Run + Queue + Transport
                        = 0.5 hr + 2.0 hr + 1.0 hr + 0.5 hr
                        = 4 hours
                        = 0.5 days
```

**Step 3: Determine safety stock**
```
Safety Stock = Average Demand × Safety Factor
             = 20 × 0.25  (25% safety factor)
             = 5 parts
```

**Step 4: Calculate total inventory**
```
Total Supermarket Qty = (20 × 0.5) + 5
                      = 10 + 5
                      = 15 parts
```

**Step 5: Determine kanban containers**
```
Container Size = 5 parts (handling, space)
Number of Kanbans = 15 / 5 = 3 kanban cards
```

### Supermarket Organization

**Physical Layout:**

```
┌─────────────────────────────────────┐
│     SUPERMARKET - TURNED PARTS      │
├──────────┬──────────┬──────────┬────┤
│ PN-1001  │ PN-1002  │ PN-1003  │... │
│  ●●●     │   ●●     │   ●●●    │    │
│  Min: 2  │  Min: 1  │  Min: 2  │    │
│  Max: 5  │  Max: 3  │  Max: 5  │    │
├──────────┼──────────┼──────────┼────┤
│ Kanban   │ Kanban   │ Kanban   │    │
│  Post    │  Post    │  Post    │    │
└──────────┴──────────┴──────────┴────┘
```

**Organization Best Practices:**
- Label every location clearly
- Use color coding by product family
- Display min/max levels visibly
- Provide kanban card storage
- Include part pictures/drawings
- Mark first-in-first-out flow
- Keep frequently used items accessible

### Supermarket Management

**Daily Practices:**
1. **Visual monitoring**
   - Check levels regularly
   - Ensure FIFO rotation
   - Verify kanban integrity
   - Maintain organization

2. **Abnormality response**
   - Stock-outs: Expedite production
   - Overstock: Investigate root cause
   - Quality issues: Quarantine and escalate
   - Kanban errors: Correct immediately

3. **Performance tracking**
   - Inventory turns
   - Fill rate percentage
   - Average levels
   - Stock-out frequency

**Continuous Improvement:**
- Reduce supermarket size over time
- Improve replenishment speed
- Eliminate safety stock causes
- Optimize container quantities
- Streamline kanban rules

## 13.4 Kanban Implementation Steps

### Phase 1: Preparation (Weeks 1-2)

**Week 1: Training and Education**
- Conduct pull system overview training
- Explain kanban principles to all affected staff
- Walk through pilot area current state
- Show videos/examples from other facilities
- Answer questions and address concerns
- Get operator buy-in and input

**Week 2: Pilot Area Setup**
1. **Select pilot product family**
   - Stable demand
   - Reliable process
   - Supportive team
   - Visible location
   - Manageable scope

2. **Physical preparation**
   - Designate supermarket location
   - Create storage shelving/racks
   - Paint floor markings
   - Install visual displays
   - Prepare kanban card storage

3. **Calculate initial parameters**
   - Determine kanban quantities
   - Design card format
   - Establish container sizes
   - Set min/max levels
   - Create initial cards

### Phase 2: Pilot Launch (Weeks 3-4)

**Week 3: System Go-Live**

**Day 1-2: Initial Setup**
- Stock supermarket to calculated levels
- Place kanban cards with containers
- Brief all shifts on procedures
- Assign champion to monitor closely
- Keep backup plan ready

**Day 3-5: Close Monitoring**
- Check system every 2 hours
- Document any issues
- Make quick corrections
- Support operators with questions
- Track inventory levels

**Week 4: Stabilization**
- Continue daily monitoring
- Document abnormalities
- Adjust quantities if needed
- Refine procedures
- Collect data on performance

### Phase 3: Refinement (Weeks 5-8)

**Week 5-6: Optimization**
1. **Analyze data collected**
   - Actual demand vs. forecast
   - Stock-out occurrences
   - Overstock situations
   - Replenishment frequency
   - Operator feedback

2. **Adjust system parameters**
   - Recalculate kanban quantities
   - Modify container sizes
   - Adjust safety stock
   - Improve visual controls
   - Simplify procedures

**Week 7-8: Documentation**
- Create standard work for kanban operation
- Document rules and procedures
- Photograph proper setup
- Create training materials
- Prepare for expansion

### Phase 4: Expansion (Weeks 9-12)

**Criteria for Expansion:**
- ✓ Pilot stable for 2+ weeks
- ✓ Stock-outs less than 5%
- ✓ Inventory within target range
- ✓ Operators confident in system
- ✓ Management support maintained

**Expansion Approach:**
1. **Add products incrementally**
   - 2-3 products per week
   - Similar characteristics first
   - Build on lessons learned
   - Maintain focus and support

2. **Expand to additional processes**
   - Upstream operations
   - Related work cells
   - Supporting areas
   - Eventually entire value stream

### Implementation Best Practices

**Do's:**
- Start simple, evolve complexity
- Train extensively before launch
- Monitor closely in early stages
- Respond quickly to issues
- Involve operators in design
- Celebrate small wins
- Document everything

**Don'ts:**
- Don't launch system-wide at once
- Don't overcomplicate initially
- Don't ignore abnormalities
- Don't skip training
- Don't blame operators for problems
- Don't abandon during rough spots
- Don't set kanban and forget

### Troubleshooting Common Issues

**Problem: Frequent Stock-Outs**
- Root causes: Demand higher than forecast, replenishment too slow, quality issues
- Solutions: Increase kanban quantity, reduce changeover time, improve quality

**Problem: Excess Inventory**
- Root causes: Overestimated demand, large lot sizes, slow consumption
- Solutions: Reduce kanban quantity, smaller containers, faster changeovers

**Problem: Kanban Cards Lost**
- Root causes: Poor card management, lack of discipline, unclear procedures
- Solutions: Card holders at each location, daily audits, retraining

**Problem: Operators Ignoring Signals**
- Root causes: Metric conflicts, not understanding importance, system too complex
- Solutions: Align metrics, retrain on principles, simplify system

## 13.5 Managing Abnormalities in Pull Systems

### Abnormality Definition

**What is an Abnormality in Pull?**
- Any deviation from standard pull operation
- Prevents smooth flow of material
- Threatens customer service
- Indicates system weakness
- Opportunity for improvement

### Common Abnormalities

**1. Downstream Stock-Out**
- **Symptom:** Customer process can't find needed part
- **Immediate action:** Check supermarket, search for parts, expedite if needed
- **Short-term fix:** Temporary increase in inventory
- **Long-term solution:** Investigate root cause (demand spike, replenishment delay, quality issue)

**2. Upstream Overproduction**
- **Symptom:** Producing process making parts without kanban
- **Immediate action:** Stop production, verify kanban signals
- **Short-term fix:** Retrain operator on kanban rules
- **Long-term solution:** Address metric system causing overproduction

**3. Broken Process**
- **Symptom:** Machine breakdown prevents replenishment
- **Immediate action:** Use safety stock, communicate to customers
- **Short-term fix:** Overtime, alternate routing, outsource
- **Long-term solution:** TPM to prevent recurrence

**4. Quality Defects**
- **Symptom:** Batch of parts defective, supermarket contaminated
- **Immediate action:** Quarantine bad parts, inspect inventory
- **Short-term fix:** Rework or scrap, rush replacement production
- **Long-term solution:** Poka-yoke, process capability improvement

**5. Demand Surge**
- **Symptom:** Unexpected large order depletes supermarket
- **Immediate action:** Communicate lead time extension
- **Short-term fix:** Expedite production, extend hours
- **Long-term solution:** Better demand forecasting, flexible capacity

### Response Framework

**Tier 1: Operator Level (0-15 minutes)**
1. Operator notices abnormality
2. Attempts immediate countermeasure
3. If unresolved, signals supervisor (andon)
4. Documents issue on response board

**Tier 2: Supervisor Level (15-60 minutes)**
1. Assesses situation quickly
2. Implements temporary fix
3. Restores normal operation
4. If cannot resolve, escalates to manager
5. Initiates problem-solving

**Tier 3: Management Level (1-24 hours)**
1. Allocates resources for resolution
2. Addresses systemic issues
3. Coordinates cross-functional response
4. Decides on parameter changes
5. Ensures follow-up actions

### Visual Abnormality Management

**Andon Board Display:**
```
┌─────────────────────────────────────┐
│      PULL SYSTEM STATUS BOARD       │

```

**Color Coding:**
- **Green:** System normal, flowing smoothly
- **Yellow:** Approaching problem (low inventory)
- **Red:** Abnormality requiring immediate response

### Problem-Solving for Abnormalities

**A3 Process Application:**

1. **Background**
   - Which process affected?
   - What is normal operation?
   - When did abnormality occur?

2. **Current Condition**
   - What exactly is happening?
   - How often does it occur?
   - What is the impact?

3. **Goal/Target**
   - What should be happening?
   - Normal operating parameter
   - Desired performance level

4. **Root Cause Analysis**
   - 5 Whys technique
   - Fishbone diagram
   - Data analysis

5. **Countermeasures**
   - Quick fixes (temporary)
   - Permanent solutions (root cause)
   - Prevention measures

6. **Implementation Plan**
   - Who, what, when
   - Resource requirements
   - Verification method

7. **Follow-Up**
   - Effectiveness check
   - Standardize if successful
   - Horizontal deployment

### Learning from Abnormalities

**Abnormality Log:**

**Monthly Review:**
- Analyze abnormality trends
- Identify chronic issues
- Prioritize improvement projects
- Share lessons learned
- Update standards

## 13.6 Pull Systems for Make-to-Order

### Challenges in Make-to-Order

**Unique Characteristics:**
- Every order potentially different
- Cannot build to stock
- Customer specifications vary
- Lead time expectations tight
- Volume per SKU low
- High process flexibility needed

**Why Traditional Pull Doesn't Fit:**
- Can't hold finished goods inventory
- Product variety too high for supermarkets
- Demand unpredictable per SKU
- Would need thousands of kanban cards

### Adapted Pull Approaches

**Approach 1: CONWIP (Constant Work in Process)**

**Concept:**
- Control total WIP, not individual products
- Release new jobs only when work completes
- Simple visual signals
- Works for high-mix environments

**Implementation:**
```
Maximum WIP = 10 jobs

Current Jobs in System:
1. Job A - Milling
2. Job B - Turning
3. Job C - Inspection
... (total 10 jobs)

When Job A ships → Release Job K from backlog
```

**Benefits:**
- Simple to manage
- Limits chaos
- Maintains flow
- Flexible for variety

**Formula:**
```
WIP Level = Throughput Rate × Lead Time
          = 5 jobs/day × 2 days
          = 10 jobs max in system
```

**Approach 2: Component Supermarkets**

**Concept:**
- Stock standard components
- Assemble/configure to order
- Postponement strategy
- Build variety at last step

**Example in CNC Shop:**
```
Standard Components (Pull System):
- Base plates (5 sizes) → Supermarket
- Shafts (10 varieties) → Supermarket
- Bushings (3 types) → Supermarket

Custom Operations (Make-to-Order):
- Final machining per print
- Custom holes/features
- Assembly per spec
```

**Approach 3: Process-Level Pull**

**Concept:**
- Pull between operations, not end-to-end
- Each process pulls from previous
- Work orders trigger first operation
- Subsequent operations pull

**Visual Board System:**
```
┌────────────────────────────────────┐
│     WORK ORDER BOARD (SAWING)     │
├────────┬─────────────┬─────────────┤
│ Ready  │ In Progress │ Complete    │
│  5 jobs│    2 jobs   │   3 jobs    │
│        │             │(ready for   │
│        │             │ Milling)    │
└────────┴─────────────┴─────────────┘

Milling pulls from "Complete" column
```

### Make-to-Order Pull Rules

**Rule 1: First-In-First-Out (FIFO)**
- Sequence jobs by arrival
- No jumping queue without reason
- Use FIFO lanes between operations
- Visual management of sequence

**Rule 2: WIP Limits**
- Set maximum jobs per workstation
- No starting new job if at limit
- Forces completion of current work
- Prevents overload

**Rule 3: Standard Lead Times**
- Communicate realistic lead times
- Based on WIP limit and capacity
- Manage customer expectations
- Use expedite fees for rush jobs

**Rule 4: Load Leveling**
- Balance workload across weeks
- Avoid accepting too much at once
- Level by process hours, not just jobs
- Use planning capacity buffers

### Hybrid Pull-Push Strategy

**What to Pull:**
- Standard components
- High-runner parts
- Long lead time items
- Consumable tooling

**What to Push:**
- Custom machining
- One-off specials
- Engineering-intensive jobs
- New product introduction

**Integration Method:**
```
[Order Entry]
      ↓
[Is it standard?] → Yes → [Pull from Supermarket] → [Ship]
      ↓ No
[Engineering Review]
      ↓
[Schedule Production]
      ↓
[Pull Standard Components] + [Make Custom Features]
      ↓
[Assembly]
      ↓
[Ship]
```

## 13.7 Pull Systems in Job Shops

### Job Shop Reality Check

**Typical Job Shop Characteristics:**
- 50-500+ different part numbers
- Batch sizes from 1 to 100 pieces
- Wide process variety
- Functional layout (all mills together, etc.)
- Frequent changeovers
- "Fire fighting" culture
- High customization

**Can Pull Work Here?**
Yes, but requires adaptation!

### Adapted Pull for Job Shops

**Strategy 1: Product Family Pull**

**Group by Similarity:**
- Similar routing
- Common processing requirements
- Comparable cycle times
- Shared fixtures/tooling

**Example Families:**
- Family A: Small shafts (turn → grind → inspect)
- Family B: Housings (mill → drill → tap → deburr)
- Family C: Brackets (laser cut → bend → hardware)

**Implement Pull Within Each Family:**
- Supermarket for common variants
- Kanban for high runners within family
- FIFO for low-volume members
- Family-specific work cells

**Strategy 2: Drum-Buffer-Rope (Theory of Constraints)**

**Identify the Constraint:**
- Bottleneck machine (e.g., 5-axis mill)
- Most expensive or critical process
- Highest utilization equipment

**Schedule the Drum (Constraint):**
- Create optimized schedule for bottleneck
- Maximize productivity at constraint
- This becomes the "pacemaker"

**Create the Buffer (Protection):**
- Time buffer before constraint
- Ensures constraint never starves
- Inventory buffer if needed

**Establish the Rope (Control):**
- Release work based on constraint consumption
- Pull signal from constraint to raw material
- Limits WIP to necessary amount

**Implementation:**
```
Raw Material Release → Upstream Operations → Buffer → CONSTRAINT → Downstream → Ship
        ↑                                                    ↓
        └────────────────── Pull Signal ────────────────────┘
               (Rope - based on constraint completion)
```

**Strategy 3: Time-Based Pull**

**Concept:**
- Divide shop into zones
- Each zone has time limit
- Jobs flow through zones on schedule
- Visual management of timing

**Example:**
```
Zone 1 (Sawing): Maximum 4 hours
Zone 2 (Milling): Maximum 24 hours
Zone 3 (Turning): Maximum 16 hours
Zone 4 (Finishing): Maximum 8 hours

Total Lead Time: 52 hours (about 2 days)
```

**Rules:**
- Job enters zone when previous exits
- Must complete within time limit or escalate
- Red/yellow/green status by time remaining
- Focus improvement on late zones

- Yellow: Approaching deadline, monitor closely
- Red: Late, immediate attention required

### Load Leveling in Job Shops

**Challenge:**
- Orders arrive randomly
- Sizes vary dramatically
- Mix constantly changing

**Leveling Techniques:**

**1. Backlog Management**
- Accept orders for future weeks
- Fill schedule strategically
- Balance large and small jobs
- Mix quick and long jobs

**2. Capacity Blocks**
- Reserve capacity for rush orders (20%)
- Standard lead time work (70%)
- Improvement activities (10%)

**3. Standard Hours Calculation**
```
Weekly Capacity = 40 machines × 40 hours × 75% efficiency
                = 1,200 standard hours available

Book orders totaling ≤ 1,200 hours
Leave buffer for variation
```

### Job Shop Pull Success Factors

**Critical Enablers:**

1. **Quick Changeovers (SMED)**
   - Reduces batch size pressure
   - Enables more frequent runs
   - Supports mixed model flow

2. **Cross-Training**
   - Operators move where needed
   - Prevents bottlenecks
   - Balances workload dynamically

3. **Quality at Source**
   - No passing defects forward
   - Inspection at each step
   - Reduces rework delays

4. **Reliable Equipment (TPM)**
   - Predictable processing time
   - Minimizes schedule disruptions
   - Enables accurate promising

5. **Visual Management**
   - Everyone sees priorities
   - Problems visible immediately
   - Status clear at a glance

6. **Standard Work**
   - Predictable cycle times
   - Repeatable quality
   - Easier planning

### Measuring Job Shop Pull Performance

**Key Metrics:**

1. **Lead Time**
   - Target: 80% of jobs within standard lead time
   - Measure: Order receipt to shipment
   - Track: By product family

2. **On-Time Delivery**
   - Target: 95%+ on time
   - Measure: Ship date vs. promise date
   - Track: Weekly trend

3. **WIP Level**
   - Target: Reduce by 50% over 6 months
   - Measure: Dollar value or job count
   - Track: Daily count

4. **Flow Efficiency**
   - Target: > 20% (high mix environment)
   - Measure: Touch time / lead time
   - Track: Monthly calculation

**Formula:**
```
Flow Efficiency = (Value-Add Time / Total Lead Time) × 100%

Example:
Total machining time: 4 hours
Lead time in shop: 5 days × 8 hours = 40 hours
Flow Efficiency = 4 / 40 = 10%

Goal: Reduce lead time to 20 hours → 20% efficiency
```

### Continuous Improvement Focus

**Monthly Improvement Targets:**
- Reduce WIP by 5-10%
- Decrease lead time by 5%
- Improve on-time delivery by 2%
- Increase flow efficiency by 1%
- Reduce inventory by $5,000

**Kaizen Events for Job Shops:**
- Setup reduction blitz
- Layout optimization
- Visual management improvement
- Work cell creation
- Scheduling system redesign

## Summary

Pull production and kanban implementation represents a fundamental shift from traditional push manufacturing to a demand-driven system. Success requires:

1. **Thorough preparation:** Assess readiness, stabilize processes, train extensively
2. **Careful design:** Properly size supermarkets, select appropriate signals, start simple
3. **Systematic implementation:** Pilot first, learn, refine, then expand
4. **Active management:** Respond to abnormalities quickly, solve problems at root cause
5. **Adaptation:** Modify pull principles for make-to-order and job shop environments

The journey from push to pull takes time—typically 6-12 months for initial implementation and years for full maturity. Patience, persistence, and continuous improvement mindset are essential.

**Key Takeaway:** Pull systems expose problems that inventory was hiding. This is a feature, not a bug—it drives continuous improvement!
